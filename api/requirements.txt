# change that had nothing to do with it: on 2026-09-30 SQLAlchemy 2.1.1 stopped installing greenlet

# ADR-0009 describes the scheduled pull requests that are meant to do the moving.

# Observability (see docs/adr/0006-opentelemetry-tracing.md)
# These five were pinned exactly before the rest of the file was. The instrumentation packages are
# on the 0.NNbN pre-1.0 line, where a minor bump is free to change span shape, so they move
# together, in one pull request, and a trace is checked in Jaeger after the deploy.
#
# HTTP rather than gRPC on purpose: no grpcio binary wheel, and no gRPC-plus-fork interaction
# with `uvicorn --workers 4`.
#
# opentelemetry-instrumentation-asyncpg is deliberately ABSENT. SQLAlchemy's instrumentation
# hooks before_cursor_execute; asyncpg's patches Connection.execute. Under SQLAlchemy-async-over-
# asyncpg both fire for one statement, giving two nested spans per query and doubling the volume.
# opentelemetry-api is listed EXPLICITLY, not left transitive: spec 0005's log formatter imports
# `opentelemetry.trace` directly to read the current trace id, so a line that used to arrive as
# somebody else's dependency is now a direct one. Pinned to the same version as the sdk, which is
# how the API and SDK are released.
#
# The exemption on the line below: drift-check's check 3 wants a NEW ADR file in the same diff
# for any added manifest name. Nothing is being added to the environment here -- the package is
# already installed and already imported directly by app/core/telemetry.py -- and the decision the
# check asks for is already written, in ADR-0007, which records that trace_id needs no new
# dependency and that opentelemetry-instrumentation-logging was investigated and rejected. A second
# ADR written to satisfy a gate is the pseudo-artifact ANTI-PATTERNS.md names.
opentelemetry-api==1.44.0  # drift-ok: made explicit, not added; decided in ADR-0007
