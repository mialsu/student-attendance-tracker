    The five-year legacy-student filter

    Done · spec 0002, one slice, verdict WORKS

    Three faults in one feature. It filtered Student.created_at while this repo's own docs, the root CLAUDE.md and the frontend's type comment all said first attendance — and for every student the entity migration created, that date was the migration date. The legacy parameter defaulted to on and no component ever set it, so the cutoff could not be switched off from the app. And it has never once fired: the app launched in November 2025, so the first silent disappearance is due around November 2030.

    A fourth fault, found while shaping, decided the scope. The filter lived on GET /api/classes/{id}/attendance, and no screen calls that endpoint — useAttendance was exported with zero callers. The list you actually read, Läsnäolot, is built on …/attendance/summary, which had no cutoff at all. So the feature hid nothing from anyone, and "keep it on by default" meant introducing hiding rather than preserving it.

    Built as one slice — not the two the handoff suggested, because api/ and client/ are two layers of one context, and landing the API half alone would bank a change no teacher can exercise. The cutoff now reads COALESCE(MIN(timestamp), created_at), lives only in find_legacy_student_ids, and the old copy is deleted. Läsnäolot shows "N vanhaa opiskelijaa piilotettu · Näytä" whenever the response's legacy_hidden is above zero, so a short list always explains itself.

    Your call on first attendance, kept and asserted. Last attendance was recommended and declined: first attendance hides a student who started six years ago and came yesterday. test_first_attendance_decides_even_when_still_attending now states that in the suite, so it can never arrive as a bug report — and reversing it starts by watching one test fail.

    341 backend tests (13 new for the cutoff), 78 client tests (5 new for the banner) INV-1: the revealed summary joins the denial suite — guard neutered, watched red, restored live: seeded 5440 / API 8099 / page 8098 — banner, reveal, delete, re-hide, and search ruff 93 -> 91, mypy 16 -> 15; client typecheck 4 and lint 16 unchanged

The one ordering rule I'd defend hardest

Don't start shared classes before the INV-1 consolidation, and don't start either before the client tests are honest.
